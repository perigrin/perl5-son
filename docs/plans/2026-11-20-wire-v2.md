> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan stage by stage. Each stage starts with its failing test. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Change the B::SoN wire so that memory, exceptions and loops are edges a checker can read: every write, call, Return and memory read carries a named `mem_in`; `inputs` holds values only; records are flagged; an `eval` join has an exceptional control edge that carries the `local` restores and the `$@` store; a loop has a back edge and an `If` for its test, built in one walk. chalk reads it and deletes `Phi::is_memory`, `Assign::is_placed` and its positional memory guessing. The eval edge and the loop edges follow as two further lockstep changes under the same version number.

## 3. The v2 wire schema

### 3.1 Top level

```json
{ "version": 2, "profile": ["mem", "eval", "loop"], "source": null, "methods": { ... } }
```

- `version` is 2. chalk's loader refuses any other value by name once v1 is deleted (stage 6).
- `profile` exists only during the migration. It lists the parts of v2 this wire obeys: `mem` (sections 3.2 to 3.4), `eval` (3.5), `loop` (3.6). The loader and the verifier enforce a part's rules only when it is listed. Stage 10 makes all three mandatory and deletes the key. (Done: neither writer writes it, and the loader and the verifier refuse a wire that has one, by name.)
- `classes`, `data_section`, `phase_blocks`, `dowarn` are unchanged.

### 3.2 A node

```
{ id, op, inputs: [..], control_in?, mem_in?, mem_out?, fields?, stamp?, head? }
```

| key | meaning | rule |
|---|---|---|
| `inputs` | value operands, in the kind's order | no memory version appears here, with the two exceptions below |
| `control_in` | the node this one follows on the control chain | unchanged |
| `mem_in` | the memory version this node reads or follows | names a version (3.3) |
| `mem_out` | `true`: this node is a memory version | needs `mem_in` and `control_in` |
| `fields.record` | `true` on an `Assign` that is a binding record, not a store | then no `control_in`, `mem_in`, `mem_out` |

Two exceptions to "inputs are values": the control nodes (`Start`, `If`, `Proj`, `Region`, `Loop`, and the new `Exc`) keep control predecessors in `inputs`, as today; a memory Phi's `inputs` are versions.

Retired by v2: `fields.memory_input` on `Call`; every trailing positional memory input (`Subscript [c,k,m]`, `Count [a,m]`, `RefType [r,m]`, `EntryWrite [e,v,m]`, `ElemRestore [c,k,s,e,m]`, `EntryDef [m]`, `PadAccess [m]`, ...); `%MEM_MIN_INPUTS`; `Proj [Loop]`.

### 3.3 Versions

A node is a memory version when it is `MemStart`, or a `Phi` with `fields.memory`, or carries `mem_out`. Nothing else is. `mem_out` is what `_place` did, stated on the wire, so no consumer derives it from a kind list.

Who carries what:

| node | `control_in` | `mem_in` | `mem_out` |
|---|---|---|---|
| `Assign` that stores (element, slice, field, shared or address-taken `my`, package variable, through a reference) | yes | yes | yes |
| `Assign` with `record` | no | no | no |
| `EntryWrite`, `CellWrite`, `Delete`, `ElemRestore`, `MakeCell`, `LocalAlias` | yes | yes | yes (stage 10: hard for all but `LocalAlias`, which B::SoN pins with `mem_in` and no `mem_out`; held by name in `SoN::Verify`) |
| sub `Call` (direct, method, indirect, dynamic_method) | yes | yes | yes |
| builtin `Call` that writes (`EffectTable` `writes` or `version`) | yes | yes | yes (stage 10: hard for `version`; a builtin that writes the world only -- printf, unlink, srand -- follows memory and is ordered by control, as `Print`) |
| builtin `Call` that only reads state | optional | yes | no |
| `RegexSubst`, `Transliterate`, `Chomp` into their operand | yes | yes | yes |
| a read: `Subscript`, `Exists`, `Count`, `Slice`, `RefType`, `PostfixDeref`, `Ref` of an element, `CellRead`, `FieldAccess`, `EntryDef` (scalar read), `PadAccess` of a variable kept in memory | only if it may die | yes | only where the producer places it as a version today (a tied read, a read `_place`d) |
| `Return` | yes | yes | no |
| `Unwind` | yes | yes | no |
| `Print` and other ordered nodes that touch no memory | yes | no | no |
| `MemStart` | no | no | is a version by op |

A call is one node with two faces, as the audit recommends (no `Proj`). The edge says which face is used: a reference from `inputs` is the call's value; a reference from `mem_in` or from a memory Phi's `inputs` is the memory after it. This is what makes `Phi::is_memory`'s case list (`chalk lib/Chalk/IR/Node/Phi.pm:55-99`) and `Builder.pm:259-308` unnecessary.

An access node with no `mem_in` is a place (an lvalue): the target of an `Assign`, the container of another access, an argument a sub call may alias, the operand of `Ref` or of a writing builtin. The verifier checks that every use of it is one of those (rule V6). No `place` flag is added; "places as nodes" stays the audit's step 8.

### 3.5 The exceptional edge (`eval` profile)

New control node `Exc`: `{"op":"Exc","inputs":[T]}`. It is the exceptional way out of the pinned node `T`. Its value is the exception in flight. `T`'s normal successor is the node whose `control_in` is `T`; a node whose `control_in` is the `Exc` runs only when `T` died.

A block eval or `try` has, besides its join Region, a **catch Region** (`fields.catch: true`, `eval_id`). Its inputs are the ends of the exceptional edges, one per node in the body that may die. The join Region takes the body's end, each `return`, and the catch path's end, so every Phi at the join has exactly as many inputs as the Region.

What stands on the edge, in order:

1. `Exc [T]`.
2. The restore of every `local` live at `T` and made inside this eval, innermost first: the same `EntryWrite` / `ElemRestore` / `LocalAlias` restore nodes the producer builds on a `next` or `last` edge, each with `control_in` and `mem_in` threaded from the edge's memory. The edge's first `mem_in` is `T` itself when `T` is a version (a call: the callee's partial writes are in it), else `T`'s `mem_in`.
3. The catch Region merges the edges; a memory Phi merges their memory; a value Phi merges the `Exc` values.
4. `EntryWrite [EntryDef($@), Phi(Exc...)]` pinned after the catch Region: the `$@` store.
5. The join Region. On the normal way in, the producer now also emits `$@ = ""` at the body's end (perl clears `$@` when an eval completes; today only chalk does this, `Control.pm:487-490`).

`our $g = 1; eval { local $g = 2; die "x\n" }; print "$g $@";` in v2:

### 3.6 Loops (`loop` profile)

- `Loop` has `inputs: [entry, back]`. `back` is the last control node of the pass: the body's end, or the latch Region where `next` edges meet it. It is the second allowed forward reference on the wire (the first is a loop Phi's back edge). A loop no path goes round has one input and no Phis.
- The test is an `If`: `If [C, cond]`, where `C` is the Loop or the last effect of the condition pinned after it (`while (my $n = shift @w)`: the `shift` call). `Proj` 0 of the `If` is the body, `Proj` 1 the header's way out. `cond` itself is an ordinary value; it is no longer pinned to the Loop.
- The exit Region keeps `head` = the Loop and takes `Proj` 1, then each `last` edge.
- A loop with no test (`while (1)`, a `goto` label loop) has no `If`; its body's first node has `control_in` = the Loop.
- A Loop's Phis have exactly as many inputs as the Loop. Trivial Phis are not emitted.
- `fields.bound` is unchanged.

## 4. How memory versions are named and threaded

**Naming.** A version is a node id. There are no version numbers and no `Proj`: the store, the call, `MemStart` or the memory Phi is the name.

**Threading (Click / libFIRM, with the node as its own memory result).**

- A write consumes a version (`mem_in`) and is the next one (`mem_out`).
- A read consumes a version and produces none.
- At a Region where the ways in carry different memory, a `Phi` with `fields.memory` merges them, one input per Region input. At a Loop the header memory Phi takes the memory before the loop and the memory at the back edge.
- A call takes the memory before it and is the memory after it. Its value and its memory are one node; the referring edge says which is meant (3.3).
- `Return` consumes the memory at the sub's end. `Unwind` consumes the memory where it dies.

In the producer this is one change to `_place` / `_pin` (`lib/SoN/FromOptree.pm:794-803`):

```perl
sub _pin ($sim, $node) {
    $node->set_mem_in($sim->memory) if !defined $node->mem_in && $node->touches_memory;
    $node->set_control_in($sim->control);
    $sim->set_control($node);
    return $node;
}
sub _place ($sim, $node) {
    _pin($sim, $node);
    $node->set_mem_out(1);
    $sim->set_memory($node) if defined $sim->memory;
    return $node;
}
```

`_call_memory_barrier` (`:5904`) sets `mem_out` too. Floating reads get `mem_in` where they are built, through a factory keyword `mem => $sim->memory` in place of the trailing input. `t/placement-one-constructor.t` grows one rule: no line outside `_pin` / `_place` / `_call_memory_barrier` sets `mem_out`.

**Why "every write is reachable from Return's `mem_in`" becomes checkable.** Walk backwards from the roots over two kinds of edge: a node's `mem_in`, and a memory Phi's `inputs`. The roots are the `mem_in` of every `Return` and every `Unwind` of the graph (a write before an uncaught `die` is observable by a caller's eval). Every node with `mem_out` must be visited. A store the next store did not name is not visited: that is the floating write, by definition (ssa-book Algorithm 12.1).

**Loop back edges.** A header memory Phi's second input is the last version of the pass. The walk reaches the Phi from whatever read or wrote after the loop (the exit names the Phi, or a version that names it), follows its back input into the body, and from there back to the Phi. The body's writes are therefore reached without any control back edge; v1 could not do this because `Return` took no memory (`lib/SoN/Verify.pm`, "WHAT THE CURRENT WIRE CANNOT EXPRESS"). A loop with no way out contributes its header memory Phi as a root (rule V4).

### 5.2 What replaces it

Braun, Buchwald et al. 2013, mapped onto the structured walk. The producer has no basic blocks; a `StackSim` (its `scope` hash, `memory`, `control`) is the current block's `currentDef`.

- **Unsealed header.** Entering a loop, the translator makes the `Loop` node and a gate `{ loop, pre => <the bindings before the loop>, phis => {} }` pushed on the sim. The header is unsealed until the back edge is known.
- **Incomplete Phis.** A variable that may be written in the loop is bound, at the header, to an incomplete Phi `Phi{region: Loop}[pre]`. Memory is one more variable: its key is `#mem`, its incomplete Phi is flagged `memory`, and it is created for every loop. The Phi's stamp starts as its init's (what `_make_loop_phi` does today when the scout says the stamp holds).
- **The body is walked once** against those Phis. `next` edges merge at the latch as they do now.
- **Sealing.** When the latch is known the translator sets `Loop.inputs[1]`, and for every incomplete Phi appends the latch's binding of its key (for `#mem`, the latch's memory).
- **Trivial Phis.** A Phi whose inputs are its init and itself (the variable was not written; the memory did not move) is trivial. The sim's binding for the key goes back to the init, the Phi is marked forwarded to the init, and the serializer writes the init's id wherever the Phi is referenced and does not emit the Phi. Recheck Phis that used it (an outer loop's). Rule V8 asserts no trivial Phi reaches the wire.
- **Exit.** The exit Region is "sealed" last, after every `last` edge has been added, as now (`_bind_break_exit_phis`, `:14900`).

Which variables "may be written" (the set W). Pure Braun creates a Phi lazily for every variable read in an unsealed block. This walker cannot do that safely yet: handlers read the bindings hash directly (70 uses of `scope_bindings`, 36 of `lookup` in `FromOptree.pm`) and decide by the bound node's class (`Constant`, `ArrayLiteral`, `PadAccess`). A Phi standing in for a variable the loop never writes would change those decisions. So W is a syntactic over-approximation: one linear scan of the body's ops (no nodes built) for every pad slot an op may write (`OPf_MOD`, `OPpLVAL_INTRO`, `OPpTARGET_MY`, an assign's target subtree, an op-assign, `preinc`-family, a foreach iterator, a `local`). An over-approximated key costs one trivial Phi, removed at sealing. A key the scan missed is caught at sealing: its latch binding differs from `pre` and it has no Phi. That stays the loud refusal it is today (`a loop body writes a variable its pre-scan missed`), never a silent wrong answer. See Q6.

**The stamp problem.** The scout's second job is to decide, before the walk, whether the header Phi may carry its init's stamp (`:14163-14186`); the walk makes stamp-dependent choices and nothing may unstamp the Phi afterwards. Without a scout the walk is optimistic. At sealing, if `_backedge_loses_stamp` says the back edge cannot confirm the stamp, the loop is rebuilt once with that key unstamped: `NodeFactory` gets a `mark` / `rollback` journal (nodes made since the mark are uncached and unhooked from their inputs' consumer lists), and the translator re-walks. This is a second walk only for the loops where the guess failed. Stage 0 measures how many those are; see Q7.

**What goes.** `_scout_once`, `_scout_mutated_targs`, `_body_writes_targ`, `_scout_condition_mutated_targs`, `_scout_placeholder`, `$IN_SCOUT` and its 13 guards, `$SCOUT_MOVED_MEMORY`, `_body_stores_memory`, `_cond_stores_memory`, `@LOOP_PHI_KEYS`. `_refuse_unscouted_writes` stays as the sealing check.

Not in this plan: `redo` and backward `goto` as ordinary edges (audit departure 18). They become possible once the header is sealed late, but nothing in the goal asks for them.

## 6. The eval exceptional edge: producer and chalk

**Producer** (`_handle_entertry`, `lib/SoN/FromOptree.pm:18841`; `_handle_entertrycatch`, `:19037`). The loop walkers already treat `next` and `last` as edges: a snapshot of the sim at the jump, the restores of every `local` of the pass placed on it (`_restore_local_elems_on_edge`, `:13377`; `_restore_locals`, `:13392`), and a merge at the target. An exceptional edge is the same thing with a different target:

- While walking an eval body, a frame `{ eval_id, save_mark, edges => [] }` is on a stack.
- `_pin` (and `_call_memory_barrier`) call `_exc_edge($sim, $node)` when a frame is open and the node may die. It snapshots the sim, makes `Exc [node]`, sets the snapshot's control to it and its memory to the edge's memory (3.5), runs `_restore_locals` on the snapshot down to the frame's `save_mark`, and records the snapshot in `edges`.
- At the `leavetry` the edges merge with `StackSim::merge` into the catch Region; the merge builds the memory Phi and, later (Q12), the Phis of rebound variables. The `$@` store is `_entry_store` (`:22537`) on the merged sim. The catch sim then joins the body's end and the returns at the join Region; `_eval_join_memory` (`:22531`) is deleted, the ordinary merge does it.

**chalk.** Today a call inside an eval tests a dying flag and branches to one shared catch block (`after_call`, `lib/Chalk/Target/LLVM/Builder/Calls.pm:29-44`; `eval_catch`, `Control.pm:454`), and `close_eval` (`Control.pm:472-548`) rebuilds the join by hand: it refuses a Region of more than one way in (`:477`), takes each Phi's last input as the catch value (`:504`), and drops memo entries a die may skip (`:525-530`).

In v2:

- `Exc [T]` lowers to a block of its own. For a call, `after_call`'s `condbr IsDying` targets it. For an `Unwind` in an eval, the die branches to it. For a may-fault division or a may-die read, the runtime check's failing arm branches to it.
- The statements pinned after the `Exc` (the restores) lower as ordinary statements in that block. The block ends with a branch to the catch Region's block.
- The catch Region is a normal merge: `EvalLeave`, `ClearDying`, then its Phis. An `Exc`'s value is the runtime's pending exception (a `%Slot`, so a `die` of a reference keeps its value: probes ex1 to ex4, ev6).
- The `$@` store is an ordinary `EntryWrite`. The join is an ordinary Region with ordinary Phis.
- Deleted: the one-way-in refusal, the last-input convention, `eval_catch`'s shared block, the `past_eval` memo surgery where the explicit Phis make it unnecessary, and WireCheck's `_locals_a_die_skips` (`:413`) and `_stores_in_a_dying_eval` (`:449`), whose shapes the edge now expresses. Probes lo2, lo16, ev12 are the acceptance tests.

### 8.3 The loader invariant (chalk, `WireInvariant`, on the raw wire before any graph is made)

Structural only; it needs no kind table beyond chalk's node classes.

- L0. `version` is 2.
- L1. Every `mem_in` names `MemStart`, a memory Phi, or a node with `mem_out`.
- L2. A node with `mem_out` has `mem_in` and `control_in`.
- L3. Every `Return` and `Unwind` has `mem_in`.
- L4. Every node with `mem_out` is reached backwards from the roots (V3, V4).
- L5. An `Assign` is `record`, or has `control_in`, `mem_in`, `mem_out`. A sub `Call` has all three.
- L6. A Phi's input count equals its Region's or Loop's; a memory Phi's inputs are versions.
- L7 (`eval`). A catch Region's inputs each lead back, by `control_in`, to an `Exc`.
- L8 (`loop`). A Loop has one or two inputs; the only forward references in a graph are a loop Phi's back input and `Loop.inputs[1]`.
- L9 (stage 10). Inputs hold values only: no node but a memory Phi names `MemStart` or a memory Phi as an input. And L5 (stage 10) holds `EntryWrite`, `CellWrite`, `Delete`, `ElemRestore`, `MakeCell` to `mem_out`.

Since stage 10 every rule holds on every B::SoN wire (no profile). That every read names a version is not the loader's: telling a read from a place takes its uses and the effect table, and that is `SoN::Verify`'s V6, the one implementation (8.2), hard in both suites.

A violation dies `GAP: wire invariant Ln: ...` with graph and node. It runs before `WireCheck`, which keeps only the rules about what chalk cannot lower (DESTROY, autovivifying reads, captured arguments written, unread derefs).

### 9.2 Open design questions, with a recommendation for each

- **Q1. Is "this node is a version" a wire flag (`mem_out`) or derived from a kind table?** Recommend the flag. It is what `_place` did; a table would be a second list in a second repo.
- **Q2. Memory Phi: `Phi` with a mandatory `memory` flag, or a new op `MemPhi`?** Recommend the flag. Both consumers already read it; V8 makes a wrong flag an error. `MemPhi` is a rename across both repos for no new information.
- **Q3. Does a pinned read stay a version where the producer places it as one today (libFIRM's Load), or do reads never make versions (Click)?** Recommend: keep what the producer does; the flag says it per node. Changing it alters chalk's `reads_before` flushing and is a separate experiment.
- **Q4. One `record` flag for both SSA-scalar records and unpinned parameter binds, or pin parameter binds as stores?** Recommend one flag now. Pinning `my @a = @_` is right in principle but changes 8 corpus and 18 chalk-lib graphs for no gate.
- **Q5. Deparser: adapter (`as_v1`) at the flip and native later, or native before the flip?** Recommend the adapter. It keeps the deparser's 9730 lines out of the critical path; stage 11 removes it.
- **Q6. Braun with the may-write filter, or pure lazy Braun (a Phi for any variable read in an unsealed loop)?** Recommend the filter. Pure Braun needs every read routed through `StackSim::lookup` (70 direct `scope_bindings` uses) and puts Phis in front of every class test in the handlers. Revisit after stage 9 if the scan proves a maintenance cost; stage 0's third number says how exact the scan is.
- **Q7. When the optimistic stamp fails at sealing: roll back and re-walk, or refuse?** Recommend: decide by stage 0's count. If it is 0 on the corpus and chalk's lib, refuse by name and write no rollback. If not, the `mark` / `rollback` journal.
- **Q8. One exceptional edge per node that may die, or one per eval?** Recommend per node. One edge per eval cannot say which `local`s were live or which memory the catch sees, which is the defect being fixed (lo16).
- **Q9. A call that dies under a live `local` in a sub with no eval (`sub t { local $g = 2; u() }`): rethrow pad now, or keep chalk's refusal?** Recommend: restores-before-`Unwind` in stage 8 (cheap, fixes lo2), the rethrow pad as a follow-up; keep the narrowed `_locals_a_die_skips` refusal for that one shape until then.
- **Q10. Does the producer store `$@ = ""` at a successful eval's end?** Recommend yes. perl does; today the fact lives only in chalk's `close_eval`.
- **Q11. The version marker: `version: 2` plus a transitional `profile` list.** Recommend as designed. The alternative, versions 2, 3, 4, contradicts "wire v2" as the name of the end state.

### 9.3 Surprises found while reading the code

- **chalk is not the wire's only consumer.** `SoN::Deparse` (9730 lines, in the producer repo) reads the decoded wire and owns the positional memory table (`%MEM_MIN_INPUTS`, `lib/SoN/Deparse.pm:173`). `SoN::Verify` imports the table from it. Stages 4 and 11 exist for this.
- **The scout is more than a double walk.** `_scout_mutated_targs` loops `_scout_once` until stamps settle (`:14146-14156`), and a foreach adds `_body_writes_targ` walks (`:14997`, `:15131`, `:15552`). A body can be walked four or more times before its real walk.
- **A graph can have no `MemStart` on the wire** while holding stores (the first example of 3.4). v2 needs it in every graph that touches memory.
- **`If` and `Loop` carry their control twice** on some paths: `Loop [5] ^5`, `If [20,22] ^20`. v2 should keep `inputs[0]` only; stage 3 drops the duplicate `control_in` on control nodes if chalk does not read it (check `JSON.pm:863-874`).
- **The eval join's memory Phi can name a store that is on a path that died** (node 14 in section 2 takes the `local`'s store through an `Unwind`). It is not only that restores are missing: the v1 join treats the `Unwind` as the body's normal end.
- **The chalk rows of the verifier baseline are stale** (c1a48dfe, before class reads), and the corpus rows still show 23 + 35 + 14 + 7 + 5 unversioned reads. Requirement (4)'s "passes" is therefore a stage of producer work (stage 7), not a consequence of the format change.
- **`memory-order-disagrees` is 228 on chalk's lib** and was never analysed (the audit's "70 unexplained", grown). Rule V5 at zero is the strictest new demand in this plan; 31 of the audit's 70 involved `LocalAlias`.
- **The bless-only arm (cr8) is an instance of a general hazard**: "does this arm need control flow" is answered by a list of op names scanned ahead of the walk (`:3054-3063`, `:18433-18436`), separate from the effect table that decides what is pinned. Any builtin the table pins and the list omits forks control without an `If`. Rule V9 checks the symptom for every kind.
